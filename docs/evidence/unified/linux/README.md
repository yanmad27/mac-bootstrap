# Linux install evidence (checkpoint B)

All credentials are DUMMY; the hand-off used `MB_TEST=1` and a mock API on 127.0.0.1. Containers are disposable and have NO systemd as PID 1. The only outbound traffic beyond package repos is `gh auth login --with-token` sending the dummy token to api.github.com (expected `HTTP 401: Bad credentials`, brief-authorised); nothing reached Tailscale.

Regenerate (repo root, colima running): `python3 docs/evidence/unified/scripts/run_linux.py <ubuntu|debian|fedora|rocky|arch>`, `scripts/run_linux_negative.py`, `/bin/bash scripts/linux-bash32.sh public/install.sh`.

- `static-checks.txt`: shellcheck 0.11.0 on `public/*.sh` exit 0; `bash -n` with Homebrew bash 5.3 and `/bin/bash` 3.2.57, exit 0; bash-3.2 construct audit; `iterm2-client.sh` byte-identical.
- `dry-run-<family>.txt` (ubuntu 24.04, debian 13 trixie, fedora latest, rocky 9, arch): the dry-run with dummy `TS_AUTHKEY`/`GH_TOKEN`/`TS_TAGS` in the env; the grep proof is in `summary-<family>.txt` and `../handoff/grep-secrets.txt`.
- `real-<family>.txt`: image@digest, platform, command, FULL installer output, exit status; then the real SSH hand-off from this Mac (client output), then postcondition probes (versions of tailscale, sshd, git, gh, node, paseo; `sshd -t`; `gh auth status` after the dummy-token login failed cleanly; git identity set; inbox removed; no key file left; no PasswordAuthentication/PermitRootLogin lines written) and an idempotent rerun. Ubuntu and Rocky ran as `tuser` with sudo, Debian/Fedora/Arch as root with `--target-user tuser`. The expected installer exit status is 3: tailscaled/sshd were not started (no systemd), honestly reported.
- Arch is `linux/amd64` under arm64 emulation (no arm64 Arch image). EMULATION LIMIT, not install.sh defects: `gh` (and a regexp-using binary) die with Go runtime panics, sshd exits 255 (OpenSSH's seccomp sandbox cannot attach, `PR_SET_SECCOMP: Invalid argument`) and `read -s -n 1` never receives a key on the emulated tty. Consequences, kept as recorded: (1) NO hand-off (SSH or paste) was possible for Arch, so the dummy gh token and git identity were supplied through the back-compat env (`GH_TOKEN`, `GIT_USER_*`); (2) the `all tools present` probe in `summary-arch.txt` is a FAIL (gh cannot run; the package is installed at /usr/bin/gh). What `real-arch.txt` does show: pacman installs, exit status 3 reported honestly, the dummy gh login failing cleanly, `sshd -t` ok, git identity set, inbox removed, idempotent rerun. Native amd64 and Arch arm64: UNTESTED. The four other families ran natively on arm64 with a real SSH hand-off.
- `negative-tests.txt`: non-root without sudo; `MB_OS_RELEASE` inert without `--dry-run`/`MB_TEST` and honoured with them; root without `--target-user`; missing os-release (override path and really removed); unsupported distro (Alpine, real run) with the package set unchanged; the detection matrix (ubuntu, debian, linuxmint, fedora, rocky, almalinux, centos, rhel, ol, arch, manjaro supported; amzn, alpine, opensuse unsupported).
- `mac-dry-run-after-B.txt`, `mac-dry-run-diff-vs-A.txt`: the Mac dry-run is identical to checkpoint A (also the fresh-Mac mock).
- `bash32-linux-dry.txt`: the Linux flow functions executed in dry-run under macOS bash 3.2.

UNTESTED: `systemctl enable --now` for tailscaled/ssh/ssh.socket/sshd and services under a real init; tailscaled running; `tailscale up` and a real tailnet join (the `file:` key path is covered on the Mac by `../handoff/target-core-stub.txt` with a stub binary); sshd under a real init; real GitHub auth; native amd64; the apt candidate decision in dry-run (the package index is not loaded there); Debian 12, Ubuntu 22.04, RHEL 8/10, CentOS Stream, Oracle, Arch derivatives (mapped, not run); firewalld/ufw states on a real host.
