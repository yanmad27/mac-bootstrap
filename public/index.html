Bootstrap a Mac for remote access

Four steps, in order: switch on Screen Sharing and Remote Login by hand, run one install command, give Tailscale an auth key (or log in interactively), and optionally set up iTerm2 on both Macs.

Commands below are built from this page's address.

1. Turn on Screen Sharing and Remote Login (by hand)

This project deliberately uses Apple's supported System Settings path for these two switches rather than scripting them. Steps apply to macOS Tahoe 26 and Sequoia 15 (Apple documents the same General › Sharing location for both). You need an administrator account.

Screen Sharing

  1. Apple menu › System Settings › General (sidebar) › Sharing.
  2. Turn on Screen Sharing, then click the ⓘ button next to it.
  3. Allow access for: choose Only these users and add just your account (safer), or All users.
  4. VNC viewers may control screen with password: leave off. Over Tailscale you do not need a separate VNC password.

Source: Apple Support: Turn Screen Sharing on or off on Mac.

Remote Login (SSH)

  1. Same place: System Settings › General › Sharing.
  2. Turn on Remote Login, then click the ⓘ button next to it.
  3. Allow access for: Only these users with your account, or All users.
  4. Allow full disk access for remote users: leave off unless an SSH session genuinely needs it (for example reading protected folders). It widens what any remote login can read.

Source: Apple Support: Allow a remote computer to access your Mac. Apple notes that enabling Remote Login reduces your Mac's security.

Check they are on (no sudo)

nc -z localhost 22 && echo "Remote Login: listening"
nc -z localhost 5900 && echo "Screen Sharing: listening"

Each line prints only when the port accepts a connection (22 = SSH, 5900 = Screen Sharing/VNC). No output means that switch is still off.

Unattended: pass secrets without leaking them

Run these four commands one at a time (pasting them together would feed the later lines to the hidden prompts). Press Enter on a prompt to skip that secret.

read -rs "TS_AUTHKEY?Tailscale auth key: "; echo
read -rs "GH_TOKEN?GitHub token: "; echo
unset TS_AUTHKEY GH_TOKEN

Why this shape: the hidden read keeps the secret out of your shell history (history records the literal $TS_AUTHKEY) and out of any command line (ps shows arguments, not variables); the variables are not exported, so only bash receives them, never curl. The script then removes them from its own environment before running anything else, so no child process (brew, curl, sudo) inherits them. This page never asks for a secret itself.

The script installs steps in this order: preflight, Homebrew, tailscale formula, tailscaled system daemon, tailscale up, git/gh/Paseo, gh auth, git identity, optional iTerm2 integration, summary. You may be asked for your Mac password more than once (sudo), for example to start the daemon.

When it finishes, start Paseo: open Paseo.app (installed in /Applications by the Homebrew cask), for example with open -a Paseo.

3. The Tailscale auth key

Can login be non-interactive? Yes: tailscale up --auth-key=file:/path logs the node in without a browser and the key never appears on a command line. Neither tailscale nor tailscaled reads TS_AUTHKEY (only Tailscale's container entrypoint does), so install.sh takes it from its environment, writes it to a private (0600) temporary file, passes only the file path to tailscale up, and deletes the file afterwards.

Generate the key

In the Tailscale admin console, Keys page, choose Generate auth key and set:

  • Reusable: off (one-off). A leaked copy is useless after first use.
  • Ephemeral: off. Ephemeral devices are removed from the tailnet when they go offline, which defeats long-term remote access to a Mac that sleeps.
  • Pre-approved: on if your tailnet requires device approval (otherwise the login waits for approval and times out).
  • Expiry: the shortest that fits (1 day). It only limits how long the key can register a device.
  • Tags: optional. A tagged device is governed by your ACL tagOwners and its node key does not expire; an untagged device stays yours but its node key expires after 180 days by default and needs a re-login.

Revoking a key does not remove devices already registered with it. Button and field names may differ slightly in the console; see Tailscale's auth keys doc.

Pass it safely

Use the unattended four-command sequence in step 2: hidden read into TS_AUTHKEY, pass to bash only, then unset. Never put the key in an --auth-key=tskey-... argument; arguments are visible to every local user through ps.

macOS caveats (Homebrew tailscale formula)

  • This is the open-source tailscaled + CLI, not the Tailscale app. It must not coexist with /Applications/Tailscale.app or the tailscale-app cask; the script stops if it finds either. Variant differences: Tailscale on macOS variants.
  • tailscaled needs root on macOS, so the script starts it with sudo brew services start tailscale; expect a password prompt (possibly more than one). No reboot or System Settings approval is expected for this variant (not tested on a live Mac, so unconfirmed).
  • If Tailscale is already Running, the script skips login and does not spend your key; with TS_HOSTNAME set it only renames the machine.
  • The script always calls Homebrew's own tailscale by absolute path, in case an older copy elsewhere shadows it in PATH.

Full write-up with source links: docs/tailscale-auth-key.md in the repository.

4. Optional: iTerm2 (both Macs)

When you SSH from one Mac to the other, iTerm2 can show a hostname badge and switch profile automatically. This needs iTerm2 shell integration on every participating Mac: the remote reports its hostname to iTerm2, and the client needs it too so iTerm2 switches back to the original profile after the SSH session ends.

Which name for --host

Use the short hostname (hostname -s) that install.sh prints in its final summary on the bootstrapped Mac, including its ready-made client command. iTerm2's shell integration reports the remote's hostname -f, usually <that-name>.local, and the profile rules match <host>.*, so the short name matches both .local and *.ts.net names. --host is not the Tailscale/MagicDNS name and not TS_HOSTNAME.

If you no longer have the summary, scutil --get LocalHostName on that Mac is usually the same value, but it can differ when macOS HostName is set or DHCP supplies a name; prefer the printed value.

This writes one Dynamic Profile, mac-bootstrap-<host>.json, into the profiles directory. What to expect: when a session SSHes into that host, iTerm2 switches to the profile automatically and shows the badge, and switches back when the SSH session ends.

Done

Check tailscale status on the bootstrapped Mac, then connect from your client with ssh <user>@<tailscale-hostname> or Screen Sharing to vnc://<tailscale-hostname>.
